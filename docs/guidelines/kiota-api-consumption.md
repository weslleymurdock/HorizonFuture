# Official Strategy: REST API Consumption with Kiota

## 1. Project Responsibilities

Horizon – Olhar do Futuro uses a tiered architecture to consume backend REST endpoints safely and consistently across platforms:

```text
┌────────────────────────────────────────────────────────┐
│             HF.Mobile (.NET MAUI) /                    │
│             HF.Web (Blazor WebAssembly)                │
│  - Host bootstrapping & root components                │
│  - Environment base URL & platform handlers            │
│  - Dependency Injection container configuration        │
└──────────────────────────┬─────────────────────────────┘
                           │ Consumes Scoped Services
                           ▼
┌────────────────────────────────────────────────────────┐
│                       HF.Shared                        │
│  - Razor pages & UI components (MudBlazor)             │
│  - PageModels (CommunityToolkit.Mvvm)                  │
│  - High-level domain-aligned UI services (e.g. AuthService)
│  - Token storage abstraction & Kiota Auth Provider     │
│  - Translates Kiota SDK models to UI results           │
└──────────────────────────┬─────────────────────────────┘
                           │ Wraps & Calls
                           ▼
┌────────────────────────────────────────────────────────┐
│                       HF.Client                        │
│  - Typed client generated by Microsoft Kiota           │
│  - Generated ApiClient, RequestBuilders, and DTOs      │
│  - Derived from OpenAPI specification                  │
│  - Zero UI logic, zero platform-specific dependencies  │
└──────────────────────────┬─────────────────────────────┘
                           │ Network Transport
                           ▼
┌────────────────────────────────────────────────────────┐
│                        HF.API                          │
│  - ASP.NET Core REST API & OpenAPI specification       │
│  - Authentication, Authorization & EF Core PostgreSQL  │
└────────────────────────────────────────────────────────┘
```

### Detailed Roles

- **`HF.Client`**:
  Contains the typed C# client generated by Microsoft Kiota (`ApiClient`, request builders, parsable models, discriminator mappings). It is strictly a client transport library derived from the API contract (`/openapi/v1.json`). It contains no Razor markup, no platform UI dependencies, and no business state.
- **`HF.Shared`**:
  Centralizes the REST consumption layer for all presentation hosts. It configures and encapsulates the Kiota `ApiClient` inside shared typed services (e.g., `IAuthService` / `AuthService`). PageModels in `HF.Shared` inject these services; they never call `HttpClient`, never construct `HttpRequestMessage`, never concatenate URL routes, and never perform manual JSON serialization.
- **`HF.Mobile` & `HF.Web`**:
  Act as application hosts. Each host registers platform-specific capabilities (e.g., Maui BlazorWebView handlers, WebAssembly browser handlers), provides configuration (such as base URL), and calls `AddPageModels()` (or `AddHorizonClient()`) to resolve shared services via Dependency Injection.

## 2. Kiota Client Generation & Update Workflow

The repository contains automated scripts and pinned tools to ensure reproducible client generation.

### Prerequisites

- .NET 10 SDK.
- Local tools manifest in [`dotnet-tools.json`](../../dotnet-tools.json), including `microsoft.openapi.kiota` (v1.38.0).
- Tool restoration command:
  
  ```bash
  dotnet tool restore
  ```

### Generation Commands

The generation process can be triggered using MSBuild or direct shell scripts:

1. **Via MSBuild Target (Opt-in in `HF.Client.csproj`)**:

   ```bash
   dotnet build -t:GenerateKiotaClient src/HF.Client/HF.Client.csproj
   ```

2. **Via Linux / macOS Script**:

   ```bash
   ./scripts/generate-client.sh
   ```

3. **Via Windows PowerShell Script**:

   ```powershell
   .\scripts\generate-client.ps1
   ```

### Script Execution Lifecycle

The generation script:

1. Restores the pinned `kiota` dotnet local tool.
2. Temporarily starts `HF.API` in background on port `5268` (Development environment).
3. Polls `http://127.0.0.1:5268/openapi/v1.json` until the specification is available, saving it to `src/HF.Client/OpenApi/openapi.json`.
4. Stops the temporary background API process.
5. Invokes `dotnet kiota generate`:

   ```bash
   dotnet kiota generate \
     --openapi "src/HF.Client/OpenApi/openapi.json" \
     --language CSharp \
     --class-name "ApiClient" \
     --namespace-name "HF.Client" \
     --output "src/HF.Client/Generated" \
     --clean-output \
     --log-level Warning
   ```

## 3. Dependency Injection and Host Configuration

Shared services and the Kiota client are registered centrally in [`src/HF.Shared/ServiceCollectionExtensions.cs`](../../src/HF.Shared/ServiceCollectionExtensions.cs):

```csharp
services.AddHorizonClient(); // Registers ITokenStore, KiotaAuthenticationProvider, IRequestAdapter, ApiClient, IAuthService
services.AddPageModels();    // Registers PageModels and calls AddHorizonClient()
```

### Registration Implementation

```csharp
public static IServiceCollection AddHorizonClient(this IServiceCollection services, string? customBaseUrl = null)
{
    services.TryAddScoped<ITokenStore, InMemoryTokenStore>();
    services.TryAddScoped<IAuthenticationProvider, KiotaAuthenticationProvider>();

    services.TryAddScoped<IRequestAdapter>(sp =>
    {
        var authProvider = sp.GetRequiredService<IAuthenticationProvider>();
        var httpClient = sp.GetService<HttpClient>() ?? new HttpClient();
        var adapter = new HttpClientRequestAdapter(authProvider, httpClient: httpClient);

        var configuration = sp.GetService<IConfiguration>();
        var baseUrl = customBaseUrl
            ?? configuration?["Api:BaseUrl"]
            ?? configuration?["ApiBaseUrl"]
            ?? httpClient.BaseAddress?.ToString()
            ?? "http://127.0.0.1:5268";

        if (!string.IsNullOrWhiteSpace(baseUrl))
        {
            adapter.BaseUrl = baseUrl.TrimEnd('/');
        }

        return adapter;
    });

    services.TryAddScoped<ApiClient>(sp =>
    {
        var adapter = sp.GetRequiredService<IRequestAdapter>();
        return new ApiClient(adapter);
    });

    services.TryAddScoped<IAuthService, AuthService>();

    return services;
}
```

### Host Differences

1. **Blazor WebAssembly (`HF.Web`)**:
   - `Program.cs` registers `HttpClient` using the browser host base address or configuration:

     ```csharp
     builder.Services.AddScoped(sp => new HttpClient { BaseAddress = new Uri(builder.HostEnvironment.BaseAddress) });
     builder.Services.AddPageModels();
     ```

   - In the browser sandbox, `HttpClient` routes through JavaScript `fetch()` APIs. Passing this instance into `HttpClientRequestAdapter` ensures all browser CORS, credentials, and streaming semantics function natively.

2. **MAUI Blazor Hybrid (`HF.Mobile`)**:
   - `MauiProgram.cs` registers platform-specific MAUI services and calls:

     ```csharp
     builder.Services.AddMauiBlazorWebView();
     builder.Services.AddPageModels();
     ```

   - On Android emulators, loopback host traffic defaults to `http://10.0.2.2:5268` instead of `http://127.0.0.1:5268`. This can be configured in mobile configuration (`appsettings.json` or typed mobile settings) without modifying shared code.
   - Credentials are held in memory by default (`InMemoryTokenStore`) and can be overridden with platform `SecureStorage` without adding MAUI dependencies to `HF.Shared`.

## 4. How to Consume API Endpoints in New UI Features

When introducing a new feature (e.g. `Courses`, `Students`, `Enrollments`):

1. **Verify or Generate the Kiota Endpoint**:
   Ensure the OpenAPI contract contains the new endpoints and regenerate `HF.Client` if necessary. Kiota exposes endpoints under `ApiClient.Api.V1.<Feature>`.

2. **Define an Abstraction in `HF.Shared`**:
   Create an interface (e.g., `ICourseService`) and result records in `HF.Shared.<Feature>`.

   ```csharp
   public interface ICourseService
   {
       Task<Result<IReadOnlyList<CourseItemDto>>> GetCoursesAsync(CancellationToken ct = default);
   }
   ```

3. **Implement the Service Using `ApiClient`**:
   Inject `ApiClient` and map inputs/outputs:

   ```csharp
   public class CourseService : ICourseService
   {
       private readonly ApiClient _apiClient;

       public CourseService(ApiClient apiClient)
       {
           _apiClient = apiClient;
       }

       public async Task<Result<IReadOnlyList<CourseItemDto>>> GetCoursesAsync(CancellationToken ct = default)
       {
           try
           {
               var response = await _apiClient.Api.V1.Courses.GetAsync(cancellationToken: ct);
               var items = response?.Value?.Select(c => new CourseItemDto(c.Id, c.Name)).ToList() ?? [];
               return Result<IReadOnlyList<CourseItemDto>>.Ok(items);
           }
           catch (ApiException ex)
           {
               return Result<IReadOnlyList<CourseItemDto>>.Fail(ex.Message, ex.ResponseStatusCode);
           }
       }
   }
   ```

4. **Inject into PageModel**:
   The PageModel injects `ICourseService` and exposes reactive properties using `CommunityToolkit.Mvvm`.
   Components bind to the PageModel properties.

## 5. Architectural Conventions

- **Base URL Configuration**:
  Resolved hierarchically from `customBaseUrl` parameter, `IConfiguration["Api:BaseUrl"]`, `IConfiguration["ApiBaseUrl"]`, `HttpClient.BaseAddress`, falling back to `http://127.0.0.1:5268`.
- **Authentication**:
  Bearer tokens are injected transparently by [`KiotaAuthenticationProvider`](../../src/HF.Shared/Auth/KiotaAuthenticationProvider.cs) through `ITokenStore`. No manual header injection is required in service methods.
- **Cancellation Tokens**:
  All asynchronous service methods take an optional `CancellationToken ct = default` and pass it to Kiota request builders (`cancellationToken: ct`).
- **Error Handling**:
  Kiota throws typed `ApiException` subclasses on non-2xx responses (such as `IdentityResultResponse`, `ResponseBaseOfTokenResponse`, or `ProblemDetails`). Services catch these specific exceptions, extract structured error lists, and return predictable `AuthResult` / `Result` envelopes rather than bubbling unhandled transport exceptions to Razor components.
- **Testing**:
  PageModels and UI components are tested against `IAuthService` mocks (e.g. `FakeAuthService`) for deterministic, zero-network tests. The Kiota client itself is tested in integration tests using a custom `HttpMessageHandler` or mock request adapter.

## 6. Real Project Code Example

### Calling Kiota in `AuthService`

```csharp
// Login implementation in HF.Shared.Auth.AuthService
public async Task<AuthResult<TokenResponseDto>> LoginAsync(Auth.Models.LoginDto request, CancellationToken ct = default)
{
    try
    {
        var kiotaDto = new HF.Client.Models.LoginDto
        {
            Email = request.Email,
            Password = request.Password,
            TwoFactorCode = request.TwoFactorCode,
            TwoFactorRecoveryCode = request.TwoFactorRecoveryCode
        };

        var tokenResponse = await _apiClient.Api.V1.Auth.Login.PostAsync(kiotaDto, cancellationToken: ct);
        if (tokenResponse is not null && !string.IsNullOrWhiteSpace(tokenResponse.AccessToken))
        {
            await _tokenStore.SaveTokensAsync(tokenResponse.AccessToken, tokenResponse.RefreshToken);
            var dto = new TokenResponseDto(
                tokenResponse.TokenType ?? "Bearer",
                tokenResponse.AccessToken,
                tokenResponse.ExpiresIn ?? 3600,
                tokenResponse.RefreshToken ?? string.Empty);

            return AuthResult<TokenResponseDto>.Ok(dto, "Login successful.");
        }

        return AuthResult<TokenResponseDto>.Fail("Authentication failed.");
    }
    catch (HF.Client.Models.ResponseBaseOfTokenResponse ex)
    {
        return AuthResult<TokenResponseDto>.Fail(ex.Message ?? "Invalid credentials.", statusCode: ex.ResponseStatusCode);
    }
    catch (ApiException ex)
    {
        return AuthResult<TokenResponseDto>.Fail(ex.Message, statusCode: ex.ResponseStatusCode);
    }
}
```

## 7. Limitations & Pending Decisions

1. **Local Offline-First Synchronization**:
   Kiota is currently used for direct online client-server communication. When the offline-first sync engine is implemented (Phase 06/07 of the roadmap with local SQLite Outbox/Inbox), background synchronizers will leverage `ApiClient` or dedicated sync endpoints, while local reads/writes will route to SQLite repositories.
2. **Android Linux Build Host**:
   Building the Android-specific target of `HF.Mobile` requires an Android SDK installation on the Linux build host. Normal tests and shared libraries run in standard `net10.0`.
3. **Platform Secure Storage**:
   `InMemoryTokenStore` is the safe, zero-dependency default in `HF.Shared`. In a production mobile rollout, a MAUI-specific implementation backed by `Microsoft.Maui.Storage.SecureStorage` should be registered in `MauiProgram.cs` to persist encrypted refresh tokens across app restarts.
